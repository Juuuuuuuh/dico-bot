# 실서버 운영 검증

코드 테스트와 실제 Discord 검증은 다릅니다. 다음 절차는 서버 소유자가 테스트 서버에서 수행해야 하며, 아직 완료했다고 보고하지 않습니다.

1. 모의 실행으로 로그인하고 서비스 로그에서 Ready를 확인한다.
2. 서버 ID·비공개 로그 채널·두 Privileged Intents·명령 등록을 확인한다.
3. 일반 테스트 계정에서 설정한 차단 도메인을 보내고 사건과 원문 조회를 확인한다.
4. 일반 메시지 6개/10초, 동일 메시지·이미지 3개/10초와 수정 후 악성 링크 삽입을 확인한다.
5. 실동작으로 전환하고 메시지 삭제와 **24시간** 타임아웃을 확인한다.
6. 봇 역할이 낮거나 채널 권한이 없을 때 실패 내역이 남는지 확인한다.
7. 운영 명령이 일반 회원에게 거부되고 운영자에게 비공개로 응답하는지 확인한다.
8. 타임아웃 해제와 확인 완료 기록을 확인한다. 메시지는 복원되지 않는다.
9. 새 봇 입장 알림, 신뢰 봇 제외, 등록된 악성 봇 ID의 선택적 추방을 확인한다.
10. `sudo systemctl restart discord-guardian` 후 기존 사건 조회와 로그인 복구를 확인한다.
11. 서버 재부팅 후 서비스 자동 시작을 확인한다. 서비스 프로세스 강제 종료 시험은 테스트 서버에서만 수행한다.
12. 디스크·저널·DB 백업·보존 기간과 외부 가동 감시를 설정한다.

## 문제 해결

- 로그인 실패: 서버에서 토큰을 재확인/재발급하고 `.env`를 수정한다. 토큰은 로그나 이슈에 붙이지 않는다.
- Gateway 4014: Developer Portal의 Message Content / Server Members Intent와 승인 여부를 확인한다.
- 삭제/타임아웃 실패: 역할 순서 및 채널별 권한을 확인한다. 관리자와 봇은 타임아웃되지 않는다.
- 명령 없음: applications.commands 초대 범위, 서버 ID, 시작 시 sync 오류를 확인한다.
- 서비스 반복 재시작: `sudo journalctl -u discord-guardian -n 100`으로 설정·파일 권한·Python 오류를 확인한다.
- DB 쓰기 실패: data 디렉터리를 전용 계정이 소유하는지 확인한다. 서비스 샌드박스는 data 이외 쓰기를 제한한다.
- 새 이미지 미탐지: 이 버전은 이미지 의미를 분석하지 않는다. 해시 등록 또는 후속 OCR/분류 기능이 필요하다.
